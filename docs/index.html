pulse

Every stack has a dev server. Serverless never got one. pulse runs your whole AWS app — API, queues, workers, DynamoDB — natively on your laptop, ready in milliseconds.

No Docker. No AWS account. Vanilla SDK code that runs unchanged in production.

$ brew install --cask geetnsh2k1/pulse/pulse
  the whole loop — live

why

the inner loop
Ready in ~100 ms, warm invokes in ~17 ms — enforced by CI, not just claimed. Code and config apply live; restarts don't exist. emulators boot containers; pulse runs native processes speaking AWS's real Lambda Runtime API
the async half
Queues deliver to workers with retries, visibility timeouts, and dead-letter queues — locally, in one console. the part deploy-and-pray never shows you and sam local can't run at all
time travel
Every trigger is recorded with its exact payload. Replay yesterday's crashing request against today's fix. Ask any request for its whole story. pulse events replay <id> · pulse logs --request <id> · pulse monitor
a CLI that teaches
Run any command bare and it asks instead of erroring. Errors ship their fix. pulse tour teaches the whole model in five minutes, hands-on. tab completion knows your functions and queues, not just the flags

honesty

pulse does one workflow completely: CRUD APIs with background jobs — HTTP, SQS, DynamoDB, Lambda.

Everything outside that subset fails loudly, with a message saying exactly what isn't supported. Never silently wrong. S3, SNS, EventBridge, Step Functions: on the roadmap, not pretended.
